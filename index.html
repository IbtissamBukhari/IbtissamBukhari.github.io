binary classification · IEEE-CIS · 590,540 transactions · 3.5% fraud

Fraud Detection System

Scores card transactions for fraud risk in real time and explains every prediction for the analyst who has to act on it.

  • Reduced 434 raw columns to 106 features and applied SMOTE only after the train/test split, so no test data leaks into training.
  • XGBoost reached 0.911 AUC-ROC on 118,108 held-out transactions, ahead of LightGBM (0.906).
  • Every score comes with its top SHAP reasons, served through a FastAPI API and an analyst dashboard.
  • Found and fixed a bug that silently ignored card and email inputs at prediction time, with a regression test.

Explainable Sentiment Analysis

Classifies reviews as positive, neutral or negative and highlights the exact words behind each prediction.

  • RoBERTa from Hugging Face with word-level LIME explanations, for single reviews or batch CSV files.
  • 81% correct on positive and negative reviews across 15,000 Amazon reviews, with an analysis of why neutral reviews are harder.
  • Quantised to 8-bit ONNX (126 MB instead of 499 MB): about 375 MB of memory and 97.5% agreement with the original model.
  • CI compares the quantised model with the original and load-tests the Docker image under a 512 MB limit.

Telco Churn Predictor

Predicts which customers are about to cancel, shows what drives each score and suggests a retention action.

  • Compared Logistic Regression, Random Forest and XGBoost and chose by recall, because a missed churner costs more than an unneeded discount.
  • Catches 283 of 371 churners in the test set (ROC-AUC 0.84).
  • Exact per-customer explanations of which details raise or lower the risk.
  • One scikit-learn pipeline (scaler fitted on training data only) behind a validated FastAPI API, with tests and Docker.
  • scikit-learn

About

Software engineer by training, ML engineer by choice.

I studied Software Engineering at Mirpur University of Science and Technology, which taught me to treat code as something other people have to run, test and maintain. Machine learning is where I apply that: a model is only useful once it is deployed, explained and checked.

My projects follow the same path. I start with the data and the question, choose the metric that matches the real cost of a mistake, and then ship the model as an API with tests, Docker and CI. I care about explainability because the people who use a prediction need to know why it was made.

My final year project detected road accidents from video with YOLOv12 and triggered emergency alerts automatically. Since then I've focused on NLP and MLOps: transformer models, model compression, experiment tracking and deployment.
