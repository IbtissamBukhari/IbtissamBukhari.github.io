Telco Churn Predictor

Predicts how likely a telecom customer is to cancel, shows exactly which details drive the score and suggests a retention action. Built on the IBM Telco dataset and served through a validated FastAPI API with a web interface.

The problem

For a retention team, missing a customer who is about to leave costs more than offering a discount to someone who would have stayed. So the model is chosen for recall, and every score has to come with a reason a retention agent can act on.

Data

The IBM Telco Customer Churn dataset: 7,043 customers and 21 columns. After converting TotalCharges to a number and removing 11 blank rows and 22 duplicates, 7,010 customers remain. Contract type and tenure drive churn the most: 43% of month-to-month customers left against 3% on two-year contracts, and nearly half of first-year customers cancelled.

Approach

  1. Encode and scale. Binary columns to 0/1, one-hot encoding for the rest, tenure and monthly charges scaled to 0–1. TotalCharges was dropped because it is close to tenure times monthly charges.
  2. Compare models. Logistic Regression, Random Forest and XGBoost on a stratified 80/20 split.
  3. Tune for recall. Regularisation strength chosen by 5-fold cross-validation on recall.
  4. Make it one pipeline. Preprocessing and model in a single scikit-learn pipeline, with the scaler fitted on training data only, so the API applies exactly what was trained.

Because the model is linear, each explanation is exact rather than approximated: every contribution is the coefficient times the difference from the average customer, and they add up to the model's output. A test checks this.

The Docker image downloads the data and trains the model at build time, so the served model always matches the library version. GitHub Actions retrains, checks the metrics against the committed results, runs the tests and smoke-tests the container.

Limitations

  • IBM's sample data describes a fictional company, so the model demonstrates the approach rather than being ready for real customers.
  • Precision is about 51%; the threshold can be raised if retention offers are expensive.
